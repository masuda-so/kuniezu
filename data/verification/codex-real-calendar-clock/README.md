# 実日時計と旧保存の検証

対象は `codex/real-calendar-clock`。通常配信の切替前の検証。

- `calendar.cjs`：1532〜1623年の33,593日の往復、月末・閏日・
  改暦境界、非実在日の拒否、760件の実装日付、新規ゲームの時計を確認。
- 同33,593日を史実DBのPython変換と照合して全一致。
- `verified-death-dates.cjs` と `tensho-peace-date.cjs` 合格。
  これらが今回生成する保存は新時計であり、旧時計移行の証明とは別。
- `history-focus.cjs` 合格。対象行軍・領有変更・山崎への帰還順と、
  各シナリオ720日を確認。生成監査は本ディレクトリへ保全した。

## 本物の旧時計で生成した保存

`6e5bd2f31ed94c7dc0f2c07f16bcadf2fafe191d` のengineと、今回変更した
4訂正モジュールを読み、現行のモデル検査器で旧時計を実行した。
モデルはサーバーと個人のブラウザ保存を操作しない。

- 今川の出陣時点：1560年6月5日、旧時刻34。
- 非実在日：1561年2月30日、旧時刻299。
- 両保存の `clockVersion` は未定義、日内進捗は0.375。
- `old-saves/manifest.json` に原コミット、入力JSのSHA256、保存SHA256、
  旧時点の軍勢表示位置を保管した。保存JSONと原出力はコミットしない。

日付選択の判定に両保存を渡し、原状態が変化しないことを確認した。
今川保存は日付選択不要、2月30日は2月28日または3月1日の選択になる。
閏年の2月30日と改暦境界も別途検査している。

以下に、計画処理と、読込画面を接続した後の検証を分けて記録する。

## 移行計画と位置継続

`clock-migration.cjs` で、原状態を変えない計画、日付選択、工事・
整備・待機・帰路の残日数、資源・兵数・処理済みイベント位置、
再計画の同一性、史実の着陣日、表示線の補間率を検査し合格した。
原文バックアップも同検査で、再利用・名前衝突時の既存内容保持・
容量エラー・保存結果を読めない場合を検証した。

関ヶ原の旧時計保存も作成し、1通常隊・2記録軍の表示点を採取した。
単純な時刻変換では家康の点が約1.93ゲーム座標単位ずれることを
再現し、記録軍の表示を次の所在記録へつなぐ処理で解消した。
`plan-1600.json` の3隊の位置差は1e-7未満。
`plan-1560.json` では今川1隊の差が0、非実在日の2選択も計画できた。

この節は計画処理の検証であり、画面での確認は次節に記録する。

## 読込画面と追加レビュー後の検証

専用Chrome、GPU無効、DPR1、940pxと335pxで18条件を確認した。
`browser-reviewed/result.json` は18条件19.180秒、JavaScript例外0件、
書き出した原文も一致。候補ファイルの専用ブラウザ内差し替えによる
確認で、通常配信とは区別する。

- 今川・関ヶ原の旧保存、木崎原の当日内の旧保存、表示キャッシュが
  欠けた軍を含む回帰検査用の保存を、各幅で取り込んだ。
- 日付・日内進捗・軍勢の表示点、兵数・資源・処理済み位置を維持。
  自動保存からの再読込でも、日付選択や移行を重複実行しない。
- 非実在日の二つの選択、取消し、ブラウザ保存枠からの取消し、
  原文バックアップ容量不足時の中断を各幅で確認。
- 保管原文を画面から書き出し、元の文字列と一致を確認。
- 狭幅の日付ボタンは年と月日を明示的に改行し、不自然な文字折返しを防いだ。

`clock-load.cjs` は、キャッシュのない実軍、木崎原の日内着陣時刻と
表示接続の終了点、選択日に未処理だった出来事の当日適用・二重実行防止を
検査して合格した。後者は検査用の人工イベントを使い、史実命題にはしない。
`tests/test_game_calendar.py` はゲームとDBの全33,593日の一致をCIで守る。

キャッシュ欠落軍は期間・指揮官を人工的に設定した検査であり、その動きを
史実の行軍と同一視しない。木崎原は旧版の実進行から生成し、
入力SHAと位置は `old-saves/special-manifest.json` に保管した。
