# GPU有効・実入力での地図描画の確認

2026-11-09、main `0adc3e11`、8000番通常配信、専用headless Chrome、1400×950・DPR1。GPUを無効化せず、SystemInfoでMetalのGPU合成・ラスタ化の有効を確認した。現在の `TKRelief.states/revision` とベース再構築数が安定してから、実ドラッグ24入力とホイール24入力を測定した。日付・兵数は不変、JavaScript例外0。

| 実縮尺 | 入力 | 実時間 | ScriptDuration差 | DevToolsCommandDuration差 | ベース再構築 | キャッシュ再利用 |
|---|---|---:|---:|---:|---:|---:|
| 1.3 | ドラッグ | 1034ms | 150.1ms | 403.2ms | 0 | 23 |
| 1.3 | ホイール往復 | 1504ms | 491.2ms | 238.1ms | 1 | 0（ズーム中の別経路） |
| 5 | ドラッグ | 991ms | 63.3ms | 317.2ms | 0 | 23 |
| 5 | ホイール往復 | 1624ms | 484.6ms | 205.0ms | 2 | 0（ズーム中の別経路） |

初回は初期カメラ演出が設定5を上書きしていたので、記録された実縮尺1.3として保持した。2回目は演出終了後に5を設定し、実camera.z=5を検査してから測定した。ホイールは上限5.5に当てない縮小→拡大の順で、最後に元の縮尺へ戻ることを検査した。

縮尺5のドラッグ中は陰影・領域のrevisionが不変。ズーム中は新しく見える範囲の読み込みを含み、revisionが変わった。操作の送信・観測にも時間が掛かるので、全実時間をアプリだけのCPU時間やFPSと読み替えない。旧GPU無効・視点API操作の測定との改善率も出さない。

画像・performance.json・計測用の一時コードはローカル証拠として保持する。地形が最終的に表示されたことと、高速ズームの全中間フレームで欠けが無いことは別に確認する。[旧測定の条件と限界](../codex-main-map-performance/README.md)。
