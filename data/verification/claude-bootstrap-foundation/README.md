# Bootstrap の土台を入れても既存の画面が変わらないことの確認

- 日付：2026-11-11。main d4d9dc90 に土台の変更を載せ、127.0.0.1:8000（Django 開発サーバー）で配信。
- ブラウザ：Claude アプリの内蔵ブラウザ（Chromium、DPR 2）。幅 1280×900 と 390×844。
- 方法：ページ内の全要素について、位置と寸法（x・y・幅・高さ）と計算済みスタイル 31 項目
  （文字の大きさ・行間・書体・太さ・色・背景・余白・枠・角丸・box-sizing・display・
  vertical-align・appearance ほか）を採る。同じ画面の状態で `bootstrap-layer.css` を
  無効にした場合と有効にした場合を比べる。
- 結果（差のあった要素の数 / 全要素数）：

| 画面 | 1280 | 390 |
|---|---|---|
| タイトル | 0 / 85 | — |
| 配置図の選択 | 0 / 99 | — |
| 勢力の選択 | 0 / 506 | — |
| プレイ画面（1560 年、今川） | 0 / 676 | 0 / 676 |
| 史実観察 | 0 / 684 | — |
| 諸家 | 0 / 1076 | 0 / 1076 |
| 操作 | 0 / 722 | 0 / 722 |
| 出典 | 0 / 1015 | — |

| 合戦図：設楽原の戦い | 0 / 830 | — |
| 合戦図：木津川口の戦い | 0 / 761 | — |

- 打ち消しを入れる前は、Reboot と同名のクラス（`.btn`、`.eyebrow`）により、プレイ画面で 169 要素、
  勢力の選択で 425 要素に差が出た。`all: revert` だけでは width・height 属性を持つ img と canvas の
  寸法が失われた（肖像が 36px → 72px）ため、これらを除いて `vertical-align` だけを戻す形にした。
- `.bs` を付けた試験用の要素では、`.card` の地と角丸、見出しの書体、`--series-*` のトークンが効くことを確認。
  `.btn` は既存の `index.css` の指定が勝つ（置き換えの段で独自の指定を外す）。
- 読み込み順の違いで、年表の欄の上端が 5px 変わることがある（Web フォントの到着前後で日付欄の
  高さを JS が測るため）。CSS の差ではなく、同じ読み込みの中での比較では出ない。
- 未実施：`tools/checks/` の実画面検査の全件。Bootstrap の JS はまだ読み込んでいない
  （ファイルの同梱のみ。最初に使う領域の置き換えで読み込む）。
