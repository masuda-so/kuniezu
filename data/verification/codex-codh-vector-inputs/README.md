# CODHベクター参照入力の検証

2026-11-07、6表現（4データセット、公開GeoJSON5種と公式SHP）を取得し、原本バイト列をgzipへ保持。展開SHA・圧縮SHA・件数・CRSをmanifestと照合した。

- 新しい入力試験15件合格：nullと重複行保持、NaN・範囲外座標・短い線・未閉合環・未知CRS拒否、原本改変検出、既存出力の保護、実データの欠損保持、CRSと年代メタデータの食い違い拒否。
- 新規試験のRuffとmypy合格。
- `node tools/checks/organization.cjs`・`infrastructure.cjs` 合格。
- 実データ全6表現から参照GeoJSONを一時ディレクトリへ生成し、検査結果を `data/audits/codh-vector-inputs.json` へ出力。

データセットは海岸1888、湖沼点1551、湖沼面573、街道47、宿場1569地物。街道ID・宿場ID・湖沼IDの重複と対象範囲を区別する。取得の地理的精度・戦国期の網羅・全形状の位相的正当性を、件数やSHA一致から証明しない。

実行時描画を変更しておらず、この段階でゲーム画面がベクター化されたとは報告しない。普段のブラウザ・保存・8000番サーバーは操作していない。

別担当が全5層の派生featureから追加idだけを除き、原本の全featureと完全一致することを独立確認した。宿場の座標が将来欠損した場合も、補完せず欠損行として記録する。

公式海岸ポリゴンZIPを通常HTTPSで取得し、WGS84地理座標のPRJ・UTF-8・SHP/SHX・CRCを確認した。PyShp 3.1.6を開発時に固定し、元の1886 PolygonとNull2を1885 Polygon・1 MultiPolygon・null2のGeoJSONとして保持する。穴・null・属性の保持と未知の投影/文字コード拒否も試験した。全形状の自己交差・包含検証とは区別する。

公式SHPの追加レビューでは、1888レコードの順序・属性、1890リング・438971頂点の座標とリング内順序、nullの位置を元ZIPと独立に全件照合し、一致した。
