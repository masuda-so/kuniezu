# 対象の同一性

2 つの識別子の関係を、1 件 1 ファイル（`<名前>.json`）で記録する。史実データベース（`docs/architecture/history-rdb.md`）の取り込みが読む。**名前が同じというだけでは登録しない。** 根拠と出典を必ず書く。

```json
{
  "id": "identity:<名前>",
  "relation": "same-site",
  "things": ["place:<台帳の場所>", "yosho:<ゲームの拠点の識別子>"],
  "basis": "同じ対象と判断した根拠",
  "source": "<出典 ID（sources の ID）>",
  "sourceUrl": "https://…",
  "locator": "出典の該当箇所",
  "checked": "2026-11-05",
  "status": "verified-in-specified-scope",
  "uncertainty": "範囲と限界"
}
```

`things` は 2 つ。1 つ目が残す側（台帳の場所など）の識別子。

| `relation` | 意味 | データベースでの扱い |
|---|---|---|
| `same-site` | 出典で、2 つの識別子が同じ対象と確認できた | 1 つの対象にまとめる。どちらの識別子でも引ける。台帳の座標があれば、それを残す |
| `represented-by` | ゲームの拠点（2 つ目）が、台帳の場所（1 つ目）を実装の上で代表している。同じ場所だという主張ではない | 対象は別のまま。台帳の場所に座標が無いときだけ、拠点の位置を借りる（根拠は `represented-by-game-site`）。出典付きの座標は置き換えない |

取り込みは、次の記録を拒む。

- 必須の項目（`id`・`relation`・`things`・`basis`・`source`・`locator`・`checked`）が欠けた記録、登録の無い出典。
- 種類の違う対象（人物と場所など）を結ぶ記録。`represented-by` は、施設・地点どうしに限る。
- どの入力も使っていない識別子を挙げた記録。残す側（1 つ目）も、入力に実在する識別子でなければならない。
- 互いに矛盾する記録：1 つの場所に代表の拠点を 2 つ挙げる、1 つの識別子を 2 つの対象にまとめる、まとめられる側の識別子をほかの記録でも使う。

1 つの台帳の場所に、複数の識別子（ゲームの拠点の識別子と、命題が使う `site:<名前>` など）をまとめることはできる。記録を 1 件ずつ分ける。

`represented-by` は、任意で期間（`period`）を持てる。ゲームの拠点が年代で別の場所を表す実装（例：1 つのノードが、ある年の出来事のあと別の城を表す）を書くためで、`same-site` には付けない（同じものは期間で変わらない）。

```json
"period": {
  "from": {"year": 1573, "calendar": "CE-year", "precision": "year"},
  "until": {"date": [1580, 3, 1], "calendar": "Japanese-lunisolar", "leapMonth": false, "precision": "day"},
  "basis": "期間の根拠（実装の出来事の日など。史実の移転の日とは限らない）"
}
```

- 端は `from`（その日を含む）と `until`（その日を含まない）。片方は省ける（開いた端）。端は旧暦の日か、西暦の年。年だけの端は、その年のどこかにあるとして扱い、1 月 1 日の確かな日に置き換えない。
- 照会（`kuniezu.history.queries.stands_for`・`represented_by`）は、その日に確かに成り立つ代表と、成り立ちうる代表を分けて返す。年だけの切り替えの年は、前後の両方を「確かでない」と返す（`settled` は None）。
- 取り込みは、確かに成り立つ部分が重なる 2 つの代表を拒む（1 つの場所に 2 つの拠点、1 つの拠点に 2 つの場所）。期間なしの代表は全期間なので、同じ場所・同じ拠点のほかの代表と必ず重なる。年だけの端どうしが同じ年で接するだけなら受ける。
- 期間付きの代表からは座標を借りない（点は期間を持たないため）。

座標は、台帳の出典付きの座標、`represented-by` で挙げた拠点の位置、同じ名前から借りた位置の順に採る。記録で挙げた拠点は、名前による借用より優先する。

2026-11-09 に、同じ名前の施設 22 件の重複を解く記録 28 件（`represented-by` 22、`same-site` 6）を足した。経緯は `docs/reports/SITE_IDENTITY_RECORDS.md`。
