# 継続作業と分担

全体ゴールは有効。フォルダ整理だけで、残る史実調査・修正まで完了したとは扱わない。

## 合意済みの仕様

- 対象年代は1560～1615年。戦略地図は日本を対象とし、朝鮮関連は史実・戦役・個別合戦・年表で扱う。朝鮮半島・明・満州・沿海州への戦略地図拡張は保留。
- 史実観察を継続。自由攻城・非史実ルート・プレイ中AI生成は保留。
- エージェントが起動・停止できるのは127.0.0.1:8000のみ。8001番の許可は撤回済みで、8001番や他ポートは起動・利用しない。127.0.0.1限定とし、待受プロセス・配信ツリー・担当を確認してから操作する。別ポートや外部公開へ広げず、専用の一時ブラウザで検証する。
- 外交関係は国境で表現。同盟の領内斜線は使わない。
- 軍は凸駒。同じ行軍だけ遠景で代表隊、近景で街道上に個別表示。別目的の隊はまとめず、横へ散らして誤認させない。
- 現代比較線・地形からの推定・史料で確定する内容を区別する。架空の経路や無根拠の移動で穴埋めしない。

## 作業一覧

要望のまとまりと完了条件は [requests.json](requests.json)。対象別の作業は `catalog.jsonl`。再生成：

```
node tools/work/build-catalog.cjs
node tools/work/tasks.cjs list --area geography --limit 12
```

一覧の queued は「機械的に未実装と判定した」ではなく、指定した完了条件を最後まで審査していないことを意味する。出典付きの一命題だけ確認できた場合は対象全体を完了にしない。

## 他エージェントへの依頼

1. 対象IDと [担当別の入口](areas/README.md) を渡す。最初に HANDOFF を読む。
2. 編集するファイルを担当記録へ登録する。同じファイルが使用中なら調整してから編集する。
3. 調査の原本・該当頁・適用年代・採否理由を保存。生成データは生成元を直す。
4. 変更と根拠を一つの短い報告書へまとめ、必要な検査と実画面の証拠を添える。
5. 完了条件を全て満たす場合だけ complete を使う。引継ぎだけなら release する。

```
node tools/work/tasks.cjs claim 対象ID --owner 担当名 --files kuniezu/static/kuniezu/対象.js,tools/checks/対象.cjs
node tools/work/tasks.cjs release 対象ID --owner 担当名
node tools/work/tasks.cjs complete 対象ID --owner 担当名 --evidence docs/reports/成果.md,data/verification/成果/検証.json --checks "対象の全完了条件を確認"
```

担当は `claims/`、完了結果は `state/` の対象別ファイルへ保存する。別担当の記録を上書きしない。期限だけで担当を勝手に解放しない。共通の `kuniezu/templates/index.html`、`engine.js`、`ui.js`、史料出力処理は特に調整が必要。

## 完了の基準

- 史実照合：対象の位置・存在年代・名称・領主/所属・役割を資料の指定箇所で審査し、実装との差異を修正する。資料が不明の項目は、何を探したかと結論の限界を記録して別の調査事項として残す。
- 表示・動作：再現手順を残し、修正後の検査と実画面で期待する表示を確認する。
- 出典：確認した事実を一命題に分け、年代と実装先へ結び付ける。URLがあるだけで確認済みにしない。
- 全体：各要望の残項目と新しく発見した不具合が解決し、必要な検査が通る。フォルダ整理、台帳生成、構造検査だけで全体を完了にしない。

受入方針だけを更新した場合は `node tools/work/build-catalog.cjs --requests-only` で要望行のみ同期し、`--requests-only --check` で確認する。対象別の行・ID・担当state・完了証拠は作り直さず、元の棚卸し生成日と方針更新日を分けて保持する。
