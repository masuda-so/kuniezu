# 地理座標と画面座標

## 現行の扱い

地点・街道の入力は経緯度を基準にし、ゲーム地図は独自の平面変換で描く。入力の配列順は `[経度, 緯度]`、単位は十進度。緯度経度の採用と、その地点・年代の史実照合済みという判定は別である。

`kuniezu/static/kuniezu/engine.js` の `G.PJ(lon,lat)` と `TKGEO` の定数は現在以下に対応する。

```
x = (lon - 129.2) * 200 * cos(36度)
y = (41.75 - lat) * 200
lon = x / (200 * cos(36度)) + 129.2
lat = 41.75 - y / 200
```

x/yはゲーム内の地図平面。画面ピクセルはさらにカメラの中心・倍率・画面寸法を適用する。`geo.js`の海岸・領域・拠点cposなどには既に投影済みの配列も含まれる。これを経緯度として再変換しない。生成元・元座標・変換条件を保持する。

標高タイルは取得側のWeb Mercatorとゲームの平面の違いを `terrain-tiles.js` が吸収する。合戦図の表示範囲も経緯度を保持するが、画面の縦横比に合わせた表示変換を行う。戦場内の模式平面図は別方式であり、0〜1の配置値を地理座標として外部地図へ渡さない。

## 他地域・外部データを追加するとき

- 元資料の経緯度と測地系、精度、年代、出典を保存する。OSM等の現代データをそのまま戦国期の街道・海岸と確定しない。
- 外部地図APIへの照合は元の経緯度で行う。ゲームのx/yやピクセルを渡さない。
- 度分秒は `度 + 分/60 + 秒/3600` で十進度へ変換する。35度41分を35.41度としない。
- 日本旧測地系、画像読図、地名検索の市町村代表点を無条件に同じ精度の地点と混ぜない。曖昧な検索結果を先頭から採用しない。
- インド等まで表示範囲を広げる場合、現在の基準緯度36度の簡易平面は歪みが増える。元座標は維持し、カメラ範囲、海岸/領域/街道/標高の変換、距離計算、旧保存の投影点をまとめて検証してから表示投影を変更する。地域ごとに任意の補正を重ねない。

この文書は将来地域の実装完了を示さない。現行コードの座標契約と追加時の境界を記録する。
