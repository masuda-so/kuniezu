# 戦役と個別合戦の範囲

戦役は複数の別名の戦闘を内包する単位、個別合戦はその局地戦として扱う。広さ・期間・名称の接尾辞だけでは決めない。開城・退去・未遂の出兵は、独立した戦闘として新設しない。

## 表示とデータ

- 戦役の入口は各戦線と個別合戦への案内にする。戦役全体に局地戦の布陣図を流用せず、自動の合戦図表示から除く。
- 既存の図が一つの局地戦を描く場合、その対象と部隊・経過を確認してから局地戦に再利用する。親の名前を変更しただけで広域の経過を局地戦へ詰め込まない。
- 子の合戦が未登録なら、その存在と出典を記録し、新しい図や参加者・位置は創作しない。
- 関ヶ原本戦と戦役全体は別の対象。既存の別戦線一覧を本戦の部隊配置へ統合しない。
- 図の対象と日付・部隊の範囲を揃える。戦役期間と局地戦の日付を同じ欄で混同しない。
- 史実DBの `Phenomenon.parent` と接続する際も同じ対象IDを使う。現在の親命題との紐付けが、全戦役の階層登録を完了していることを意味しない。

## 調査記録

`data/research/reviews/battle-campaign-scope.json` は既存111場面の分類候補で、採用済みの史実命題ではない。資料本文の読了記録、部分確認、コードで確認した描画範囲を別に保持する。根拠のない候補を描画やDBへ自動適用しない。

## 受入条件

1. 採用した戦役では布陣Canvas・再生操作を表示せず、子の合戦と出典へ移動できる。
2. 個別合戦では対象の範囲・部隊・経過が一致し、元の図を破壊しない。
3. 自動表示の自家関連判定、自然終了、一覧からの手動閲覧、戻る操作を維持する。
4. 広幅・狭幅の実画面で一覧・戻り先・再生の有無を確認する。
5. DBへ採用する階層は自己参照・循環・異なる年代の同名戦闘の誤統合を拒否し、再取込で複製しない。
