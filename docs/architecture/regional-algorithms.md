# 地域を増やす際の共通処理

2026-11-01のユーザー方針：日本・朝鮮・今後追加する地域で共通のアルゴリズムを使う。地域別の例外で見た目や機能差を増やさない。

## 現状確認

|処理|共通部分|残る地域差|
|---|---|---|
|地図座標・カメラ|G.PJ、clampCam、全画面境界|データの収録範囲|
|行軍|visualBetween、visualPathPoint、時計、向き、凸駒|史料付き進路の有無・道路データ密度|
|標高画像|入力範囲の交差判定、タイル選択、待ち行列、取消、中間層、地図投影、キャッシュ|GSI/Mapzenの標高復号のみ異なる。以後の陰影・着色・投影は共通化済み|
|河川|線幅1.1/z、画面上での表示判定|全投影河川でriverGeometry/riverVisible/riverPathを共通化済み。入力の収録密度は異なる|
|領域|同じ領有表示・外交判定|表示時は全領域Chaikin2回、海岸1回へ共通化済み。元データの現代admin1＋Voronoi由来という課題は残る|
|街道|roadDisplay、経路探索、表示・整備|史料の経由地・近現代比較線の有無|
|施設|YOSHO、同じ年代判定・効果計算|収録対象の偏り・史料照合の不足|

## 変更方針

- 地域固有の描画分岐を増やさず、標準入力（投影済み形状、時点、精度・出典）へ変換して同じ処理へ渡す。
- 標高は標準DEMから同じ陰影計算を使う方向を検証する。取得先の差は読込部分で吸収する。日本の既存陰影を単に粗い画像へ置換して共通化したことにしない。解像度、地形の明るさ、速度を日朝の同縮尺で確認してから適用。
- 河川は同じ形状処理・線幅・可視判定を使う。存在しない細流を補う手段として平滑化しない。
- 行政区分の歴史的差異は入力データの差として保持する。史実の八道と、ゲームの拠点管理領域を混同しない。共通の平滑化を施しても史実の境界になったことにはならない。
- 道路の閉路・城への接続を、日朝で同じ検査へ通す。近現代道路の探索上の往復は史実の支線として採用しない。

この文書は現行差分の監査と実装方針。全処理の統一完了を表すものではない。
