# 人物と城の時空間の記録を拡充する

<!-- EGM：草稿を Goldfish 3 体（comprehension・design・zoom-out）で点検し、指摘を反映した版。利用者の承認 2026-11-14 -->

## Overview

史実データベース（Django の `kuniezu.history`、以下「史実 DB」）を、利用者の言う「時空間キューブ」の形に育てる。時空間キューブは、時間地理学の考え方で、地図を床に、時間を高さにした立体に記録を置いたもの。人物は時間とともに動く線（軌跡）、城は築かれてから消えるまで立つ柱になる。同じ時に同じ城にいた人物は、柱の上で線が交わる。

- **人物（動く）**：生まれてから死ぬまで。どこにいたか（座標での移動）、誰に仕えたか（主従）。
- **城（動かない）**：築かれてから消えるまで（現存なら今まで）。どの家が持っていたか、誰が城主・在城だったか。
- **日付**：史料の旧暦、ISO 8601（先発グレゴリオ暦）、当時の西暦（1582-10-04 まではユリウス暦）、通日（ユリウス通日）をすべて出せる（利用者の決定 2026-11-14）。

## 用語

- **確かめた命題**：出典の該当箇所で確かめた 1 つの事実（`data/research/curated/claims/`、1 件 1 ファイル）。
- **所在の記録**：人物がある場所とどう関わったか（`curated/locations/`）。
- **支配の記録**：城をどの家が持っていたか（`curated/control/`、2026-11-13 に作った）。
- **綱文**：東京大学史料編纂所の『大日本史料』の各条の見出し。日付と要旨がある。
- **典拠**：国立国会図書館の典拠や Wikidata の、人物を同定する記録。見出しに生没年を含むことがある。
- **比較値**：典拠などにある値で、出典の本文では確かめていないもの。史実としては採らず、調べる手掛かりにする。

## The Problem

器はあるが中身が少なく、しかも人物と城の記録が DB の中でつながらない所がある（2026-11-14 に調べた）。

**中身の少なさ**

| 要るもの | 今 | 足りない |
|---|---|---|
| 人物 | ゲームの武将など 413 人 | — |
| 生年 | 命題 1 件（`birth-year`） | ほぼ全員 |
| 没年 | 命題の没日 58 件ほか、合わせて 74 人 | 339 人 |
| 人物の所在・移動（座標付き） | 年表を写した未照合の記録が中心。出典で確かめたものは 28 件 | 一生をつなぐ点 |
| 人物どうしの主従 | ほぼ無い（家どうしの臣従・同盟が約 50 件） | 誰が誰に、いつからいつまで |
| 城の存続（築城〜消滅） | 存続期間 115 件。出典で確かめたのは 8 件 | 出典付きの築城・廃城・焼失の日 |
| 城の持ち主 | 支配の記録 10 件 | ほぼ全部 |

**つながらない所**

1. **城の鍵が 2 つある**：所在の記録は登録済みの場所（`place:…`、42 か所）しか受けず、支配の記録はゲームの城（`castle:…`）しか受けない。同じ城でも、城主は `place:` 側、持ち主は `castle:` 側に入り、1 本の柱にならない。
2. **人物の登録が足りない**：所在の記録は、登録済みの人物（`curated/people/`、約 60 人）しか受けない。413 人の大半の所在は入れられない。
3. **軌跡に出ない記録がある**：`history_query --path` は移動の事象しか拾わない。城主就任は支配の事象、生没は存廃の事象として取り込まれるので、軌跡に出ない。
4. **置き場所が 2 つある記録がある**：築城・廃城は、命題（`castle-construction`・`abandoned`）と支配の記録の両方に書けてしまい、二重に数えるおそれがある。

## Goals

1. 日付を 4 つの形で出す。
2. 城の鍵と人物の登録を整え、人物ごと・城ごとの記録が 1 本の線・柱にまとまるようにする。
3. 人物の生没、城の存続・持ち主・城主、人物の所在を、出典付きで足す。
4. 人物どうしの主従を持てるようにする（新しい記録の種類）。
5. 全体を決めて分ける（MECE）。対象の全体と、記録の種類ごとの状態を機械で数えて報告する。

## Non-Goals

- 見せ方（ゲームの地図の軌跡、立体のキューブ）。中身が増えてから別の設計で行う。
- 史料にない位置や日付の推定（本拠にいたはず、移動の途中の位置など）。
- 1532 年より前（中期目標の第二段階、応仁の乱から）。暦の表（`koyomi.js`、今は 1532〜1623 年）を広げるときに扱う。

## Technical Plan

### 1. 日付の 4 つの形

史実 DB は事象ごとに、通日の幅（`jd_start`・`jd_end`）と、史料の旧暦（年・月・日・閏月）と、精度（`precision`：日・年・期間）を持つ。ISO 8601 と当時の西暦は通日から計算できるので、DB には足さず、出すとき（`history_query` の出力、ゲーム用の書き出し）に計算する。

| 形 | 例（桶狭間の戦い） | 計算 |
|---|---|---|
| 旧暦 | 永禄 3 年 5 月 19 日 | 史料のまま |
| 当時の西暦 | 1560-06-12（ユリウス暦） | `dates.jd_to_western`（今ある） |
| ISO 8601 | 1560-06-22（先発グレゴリオ暦） | `dates.jd_to_iso`（新しく足す） |
| 通日 | 2291011 | DB の値 |

**精度を偽らない**：日まで分かる事象だけ 1 日の日付で出す。年・期間の事象は、ISO 8601 の期間の書き方（`始まり/終わり`、例：`1575-02-10/1576-01-30`）で出す。片側しか分からない期間は、分からない側を `..` で書く（ISO 8601-2 の開いた期間）。出典が両端を述べていない期間（`bounds_asserted` が偽）は、その旨を並べて出す。

### 2. 城の鍵と人物の登録

- **城の鍵を 1 つに**：所在の記録でも、ゲームの城の鍵（`castle:<id>`、支配の記録と同じ）を受ける。取り込みは支配の記録と同じく、`castle:<id>` を史実 DB のゲームの拠点（`node:` か `yosho:`）に結ぶ。今ある `place:` の 42 か所は、城に当たるものだけ、同一性の記録（`curated/identities/`、`same-site`）で城と結ぶ。
- **置き場所の決まり**：
  - 城の持ち主（家）と、築城・廃城（持ち主が「なし」から家へ、家から「なし」へ）は、支配の記録を正とする。同じ出来事の命題があれば、支配の記録の `claim` で参照し、二重に数えない（数えるときは支配の記録だけを数える）。
  - 城主（人物）は所在の記録（`held-castle-lordship`）を正とする。家の持ち主とは別のこと。
  - 焼失・破却は命題（`burned` など）のまま。
- **人物の登録**：ゲームの武将の一覧から、まだ登録の無い人物の登録（`curated/people/`）を機械で作る。名前で結んだだけで典拠で同定していないことを `identityBasis: "game-name"` で示す。典拠で同定した人物と区別する。

### 3. 軌跡の定義

`history_query --path <人物>` が出すのは、その人物の次の事象を日付の順に並べたもの。

- 移動・所在の事象（今と同じ）
- 城主就任（所在の記録の `held-castle-lordship`。DB では支配の事象）
- 生まれた日と死んだ日（存廃の事象。軌跡の両端）

場所の無い事象（生没の多く）は、場所なしで並べる。

### 4. 棚卸し（MECE の出発点）

新しく調べる前に、今ある材料を機械で表にする（新しい管理コマンド、例：`manage.py history_inventory`）。

- **全体**：人物は登録の全員（2. の後で 413 人）。城は、ゲームの城のうち城であるもの（倭城・干拓地など城でない施設を除く。条件は実装で決めて報告書に書く）。
- **状態**（記録の種類ごとに、どれか 1 つ）：
  - **確定**：出典で確かめた記録がある
  - **比較値だけ**：典拠・ゲームの値などはあるが、出典で確かめていない
  - **決まらない**：調べたが決められなかった（記録として残す。支配の記録の `undetermined` と同じ考え）
  - **未着手**
- **記録の種類**：人物は生年・没年・所在・主従。城は築城・消滅・持ち主・城主。

報告書には、全体・状態ごとの数の表を付ける。数は管理コマンドで再現できる。

### 5. 主従の記録（新規。最後に、試行と一緒に作る）

1 件 1 ファイル（`curated/service/`）。形は支配の記録にならう。

| 項目 | 要否 | 内容 |
|---|---|---|
| `id` | 必須 | `service:<人物>-<主君>-<最早日の年>-<連番>` |
| `person` | 必須 | 仕えた人（`person:…`） |
| `lord` | 必須 | 仕えた先。**人物**（`person:…`）。出典が家しか述べないときだけ家（`clan:…`） |
| `kind` | 必須 | 最初は `vassal`（家臣）だけ。種類は試行で足す |
| `time` | 必須 | 時点か期間 |
| `boundsAsserted` | 期間のとき必須 | 出典が始まりと終わりを述べているか |
| `summary`・`source`・`locator`・`evidenceDepth`・`checked`・`checkedBy` | 必須 | 支配の記録と同じ |

- 家どうしの臣従・同盟（`relation` の `submit` など）は今のまま。主従の記録は人物どうし。
- 当主が替わったときは、新しい当主への記録を別に足す（主君は人物なので）。
- 異説・重なりの検査は人物ごとに行う。

## Risks

| 危険 | 対策 |
|---|---|
| 名前だけで結んだ人物（`game-name`）を、同定済みと取り違える | `identityBasis` で区別し、棚卸しにも分けて数える |
| 比較値を史実として採ってしまう | 比較値は棚卸しの状態だけに使い、命題にするのは出典で確かめたものだけ（今の決まり） |
| 暦の表の外（1532 年より前）の記録が拒まれる | 第二段階で暦の表を広げる。それまでは扱わない |
