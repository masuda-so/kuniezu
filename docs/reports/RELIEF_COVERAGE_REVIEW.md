# 標高の中間表示と提供範囲外の要求

2026-11-01。前回の豆満江画面の矩形状の解像感差を、5/10/20秒の実画面とCDP応答・描画タイルで再確認。

## 確認と訂正

差が見えたのは読み込み途中の中間解像度画像だった。詳細DEM195枚は2回の観察とも10秒時点で完了し、20秒画像では当初の大きな矩形差は消えた。先の調査中の「読み込み完了後にも残る」という見立ては訂正する。隣接2枚の元DEMも入力へ保持したが、これを元データの品質欠陥の証明とはしない。

一方、朝鮮の画面でも日本用のPath2Dマスクが存在するだけでGSI画像層の取得を始めていた。実際の画面に日本の陸地がなくても182枚を要求し、全て404となった。クリップは描画だけに効き、取得範囲の制限になっていなかった。

## 修正

TKTerrain.setCoverage(provider,polygons)により、提供先を限定する入力ポリゴンの包絡矩形と各タイルの交差を共通に判定。日本の陸地データをGSIの入力範囲へ登録し、範囲外のタイルは取得・キャッシュ描画の候補から除外する。任意の提供元にも使える仕組みで、朝鮮の地域名を特例判定していない。包絡矩形なので海域の不要取得を完全にゼロにする保証はない。

診断用statsへ実際の描画層と個別タイルの成否を追加。毎フレームの描画更新番号取得はgetRevision()へ分離し、診断用配列を毎フレーム複製しない。

## 結果と限界

同一豆満江視点で対象GSI詳細要求182→0。全体の失敗185→1（開始時の別タイルを含む）。10秒時点の待機105/取得中6→待機0/取得中0。ただし両観察でDEM自体は10秒時点に195枚完了しており、DEM到着時間の短縮やFPS改善の割合は証明していない。data/audits/relief-coverage-review.json。

terrain-transitionで範囲外の要求・既存画像を除外すること、common-reliefで陰影を確認。専用Chromeで日本と朝鮮を再確認し、日本のGSI DEMが読み込まれることも検査。data/verification/relief-coverage-regional/、例外0。範囲判定の前後はrelief-seams/とrelief-seams-coverage/。元DEMとSHAはdata/inputs/terrain-diagnostics/。

通信が遅い場合、中間解像度を表示する期間は引き続き存在する。実データより細かな地形を捏造したり、全体をぼかして見えなくする修正ではない。継続ゴールactive、サーバー操作なし。
