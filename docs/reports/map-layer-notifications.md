# 地図層の遅延読込後の再描画

標高・境界線・河川の読込完了通知が、領域画像の初期同期に付けた行コメントへ飲み込まれていた。結果として領域画像の通知だけが登録され、停止したカメラで遅れて復号された標高が到着しても、下地の更新と描画ループの再開が予約されなかった。

通知の登録を独立行へ戻し、初期同期の説明は単独のコメントとした。領域画像だけは範囲を同期し、全4層が下地の無効化・ループの再開を行う。描画アルゴリズム・タイルの正本・標高データ・史実進行は変更しない。

回帰検査 `tools/checks/map-layer-notifications.cjs` は、実際のUI登録部分を実行して4層の通知、初期範囲同期、層が未提供の場合の挙動を確認する。変更前は標高・境界線・河川の登録不足で失敗し、変更後は合格した。`offline.cjs` から呼ぶことで既存のCIに含める。

専用一時Chromeでは、標高WebPの復号完了を一時保留し、ゲームを停止して同じカメラから保留分を解放する比較を行う。サーバーは起動せず、Djangoと同じテンプレートから生成した一時ページを使う。手元の生成済み地図キャッシュは読み取り再利用し、地図の再生成や精度の検証とは扱わない。

検証の結果と範囲は [実画面証拠](../../data/verification/codex-map-layer-notify/README.md) に記録する。この修正で全てのズーム性能問題が解消したとは断定しない。
