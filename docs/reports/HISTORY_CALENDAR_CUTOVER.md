# 史実DBの西暦改暦境界

DBの `western_to_jd(1582, 10, 5)` がJDN2299151を返し、前日の10月4日（2299160）より9日前へ戻っていた。入力年月日をユリウス暦で算出した日番号を使って改暦を判定していたため、欠番の10月5〜14日がグレゴリオ側へ入ることが原因。

ゲームとDBの既存方針である、10月4日までユリウス暦・15日以降グレゴリオ暦を維持し、その間の欠番だけValueErrorで拒否する。年単位の境界や日本旧暦の換算は変えない。精密な西暦入力が欠番なら取込トランザクションを中止し、誤った別日を保存しない。

国立天文台「日本の暦日データベース」の西暦規則も、1582年10月15日以後をグレゴリオ暦、それ以前をユリウス暦とする。参照：<https://eco.mtk.nao.ac.jp/cgi-bin/koyomi/caldb.cgi>（2026-11-08、「ご利用にあたって／西暦」）。

長篠の日本暦1575年5月21日は現月表からJDN2296506となり、ユリウス暦6月29日と先発グレゴリオ暦7月9日は同じ日。資料の表記差を理由にゲーム内の開催日を移さない。これは月表と独立した西暦計算式による照合であり、天文台の個別検索結果を取得したという意味ではない。また日本暦1592年4月14日と朝鮮暦の同名月日には1日差があり、日本暦変換で釜山鎮の日付を置換しない。

検証：欠番10日の拒否、1582年の全実日付のJDN往復、長篠の二種類の西暦対応、日朝の別暦を追加検査。史実DBの日付・取込・検索の63件が合格。Ruffとmypyも対象2ファイルで合格。地図と部隊の時計は変更していない。
