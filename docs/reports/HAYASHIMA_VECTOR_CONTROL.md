# 早島の元形状と細かな管理境界を回復する

現行ベクターには、既採用の8m丘陵形状の約0.99haが1560〜1583年の陸から欠け、1584年以降の追加陸へ含まれていた。元入力`data/inputs/kojima-coast-review/hayashima-upland-comparison.geojson`のfeature 0（SHA `5baa4f521b379934eb8df9ce66c757a08ff6647cb2799b7c19b6bceee3704f90`）と採用定義`kuniezu/map/edits/applied/hayashima-upland.json`へ照合した。

元形状から不足分だけを基準陸へ戻し、1584年の追加陸から除いた。1584年以後の陸形状と水域は不変。岸線は早期だけの3地物と追加1地物へ反映した。候補との幾何同一を保ちながら、対象外5,167地物の表現と無変更の成分・リングの座標順序を保持した。補間・丸め・新しい汀線の創作はしていない。8m形状は既採用の比較・補正根拠であり、戦国期の精密汀線を確定する資料ではない。

物理陸だけ直すと、100mの管理画像で海だった部分が無色になり、平滑化した旧領域でも約458㎡が選択できなかった。そこで同じ復元部分だけを`control/subcell.geojson`に保持する。管理キーは旧採用定義の`castle:bmatsuyama`を引き継ぐ。新しい領主推定・史実知行命題は作らない。1584年の元マスクの4部分セルも同じキーであり、以後の管理キーは変えない。

共通ベクター読取器が適用期間・穴・投影を処理し、同じ形状を色と選択へ使う。国色は管理画像をこの部分だけ除いてから1回塗り、色が取得できない場合は元の国色を保持する。物理陸の外へは塗らず、未知の城キーは選択の既存処理へ戻す。地域固有の座標補正や実行時の形状合成は入れない。

同時期の細かな管理地物どうしは重ねない。これは逆クリップの前提で、`tests/test_subcell_control.py`が検査する。通常ビルドは他の正本と同様に無改変コピーする。読込は必要な全ファイルの検査が済んでから一括で有効化する。

検証：元丘陵の全期間被覆、管理形状の元丘陵内への限定、水域との交差なし、期間、Nodeの色・選択・穴・不正キーの原子的拒否、配信バイト一致を確認。Djangoの実配信で旧選択欠落2地点を両幅から選択でき、合成キャンバスで二重塗り防止と取得失敗時の色保持も確認した。[検証記録](../../data/verification/codex-hayashima-vector-control/README.md)。
