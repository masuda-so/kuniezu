# 合戦図の位置保持と個別選択

## 問題と修正

画面端へ駒を押し込む処理、密集時に駒本体を離す処理により、表示幅や地区切替で
部隊が別の地理位置へ移ったように見えた。駒は投影位置のまま描き、名札・顔・旗の
画面内調整と分離した。同地点の部隊は本体クリックで候補を開き、各隊を選択できる。
画角外の駒は画面端へ移さず、該当地区への切替で確認する。
削除した位置補正のキャッシュと、各描画で全隊を走査していた未使用の近接計算も除く。

推定の動きは一定の1000×700平面で計算してから表示幅・倍率へ投影する。
史料の座標 `point`、表示中心 `screenPoint`、逆投影 `renderedPoint` を分離し、
推定配置の元座標はnull、模式図・城郭平面図も地理座標を返さない。
史料に基づく段階移動と関ヶ原の不参戦5隊の待機は維持する。

独立レビューで推定配置隊の本体クリックが空の詳細になる不具合も確認した。
記録済み・推定の両群を検索し、同地点の全隊を候補にする。
選択パネルの顔枠も寝返り時の陣営に追従し、逆再生で戻る。ボタンと顔画像ノードを
作り直さず、陣営が変わった場合だけ顔枠を更新し、閉じたパネルを再表示しない。
推定配置の輪郭だけを破線にし、記録地点からの推定移動は実線の駒に点線の軌跡とする。

## 検査と実画面

`node tools/checks/battle-viewport.cjs` は関ヶ原・高天神の幅・倍率・時刻120条件を
実Canvas描画命令で照合する。画角内の全隊が一度ずつ描かれ、推定駒も検査対象に含める。
同地点の選択、画角外の当たり判定、模式図の座標非生成、名札・旗の画面内調整も確認する。
フォント幅は近似なので、実Chromeの検査と併用する。
関ヶ原の待機5隊/他40隊の互換、推定移動109合戦、基本検査、フォルダ・担当管理、
施設・速度・保存の基盤検査、アセット確認値も合格。

`battle-viewport-browser.cjs` は起動済み8000番に専用Chromeで接続し、幅と地区の切替、
5合戦の位置不変、推定隊の実クリックを検査する。
[実画面の条件と証拠](../../data/verification/codex-battle-viewport/README.md)を参照。
共有配信元へ修正を適用済みと扱わず、候補差分を差し替えた検査として記録する。

## 範囲

同じ投影位置を守る修正であり、既存の推定経過を史実の確定位置へ昇格させない。
密集した関ヶ原の全体図は地区別表示と選択を併用する。全111合戦の史料配置や
全画面の可読性を、この検査のみで完了とはしない。
