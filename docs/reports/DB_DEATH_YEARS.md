# 史実 DB の没年をゲームに効かせる

2026-11-14。利用者の依頼「データベースがちゃんとゲームに反映されているのかも確認して」と、その結果を受けた選択「DB から書き出す」による。

## 確認したこと（変更前）

- ゲームに届いていたのは城の持ち主だけ（`owners.js`、公開の書き出し）。今の DB からの書き出しは `tools/checks/fixtures/owners-trial.js` と区間が同じで、`owner-timeline.cjs` は合格（吉田城が記録の日に持ち主を替える）。
- 没年は `hist.js` に手で書いた `TK.DEATH_Y` と、年表の死去の出来事（`k:'death'`・`kill`）で決まり、DB を読んでいなかった。生年・改名・所在・主従もゲーム側の別のデータ。
- DB で確認済みの没年 124 人を、ゲームと突き合わせた（年表の出来事を先に、無ければ `TK.DEATH_Y` を、DB の別名すべてで引く）。

| 結果 | 人数 |
|---|---|
| 日まで一致 | 34 |
| 年は一致（日がずれる） | 45 |
| 食い違い | 4（佐久間信盛 DB 1581／年表 1582-2-1、吉川元春 DB 1586／年表 1587-1-1、岩城重隆 DB 1569／`DEATH_Y` 1570、市川経好 DB 1585／`DEATH_Y` 1578） |
| ゲームに没年なし | 34（徳川信康・石川数正・池田輝政など） |
| ゲームの終わりより後（1616 年〜） | 7 |

## 変更

- `kuniezu/history/death_export.py`：確認済みの `death-date`（本人が主体）から、名前ごとの没年（ゲームの読む西暦の年、最も早い日の年）と日の範囲・出典を書く。DB の別名すべてで書き（木下秀吉で豊臣秀吉を引ける）、二人が共有する名前は書かない。`export_game_data` が `owners.js` と並べて `deaths.js` を書く。
- `kuniezu/static/kuniezu/history/deaths.js`：既定は空（`TK.DEATH_YEARS=null`）。公開の書き出し（`scripts/build_static.py`）が DB のもので置き換え、頁の `?v=` を付け直す。
- `kuniezu/static/kuniezu/death-years.js`：`TK.DEATH_YEARS` があれば `TK.DEATH_Y` を上書きする。置き換えた名前と元の年は `TK.DEATH_Y_REPLACED`。年表の死去の出来事と、保存の照合に使う年表の署名は変えない。
- 今の DB では 124 人・138 の名前。手書きの年を替えるのは 3 人（佐久間信盛 1582→1581、岩城重隆 1570→1569、市川経好 1578→1585）、新たに年が付くのは 78 の名前。佐久間信盛は年表の死去（1582-2-1）が残るので、年表どおりに世を去る（年表に後で出る人は、その出来事まで生きる）。

## 残り

- 吉川元春・佐久間信盛の年表の日付（食い違い）と、日がずれる 45 人は、年表の出来事を直すかを別に確かめる（今回は年表を変えない選択）。
- 生年・改名・所在・主従は、まだ DB からゲームに届かない。
- 開発サーバーは既定の空の `deaths.js` を読むので、手書きの没年のまま（城の持ち主と同じ）。

## 検査

- `tests/test_death_export.py`：確認済みだけ・本人だけ・別名すべて・共有名は除く・旧暦の年が西暦 2 年にまたがるときは先の年・命令が `deaths.js` を書く・既定は空。
- `tests/test_build_static.py`：書き出しが `deaths.js` を作り、頁がその hash で読む。
- `tools/checks/death-years.cjs`（CI に追加、約 3 秒）：既定では何もしない。固定の書き出し（`fixtures/deaths-trial.js`、2026-11-14 の DB から作成）では、DB の年が優先され、DB に無い 147 の名前は手書きのまま、年表の署名は同じ。
