# 過去年代の選択と再生起点の修正

## 問題と変更

過去年代の再生は1560年5月1日を起点として表示していたが、登録済みの
初期シナリオは開始日の補正後、実際には1560年6月5日だった。
また、その年代に存在しない家で開こうとすると、エンジンの現在状態が
失われていた。再生準備中に、別年代の出来事が通常画面へ通知される問題もあった。

`G.historyOrigin()`で登録済みの最も早い親シナリオの起点を取得し、
時の帯と再生の入口を共通化した。控えのラベルは初期化後の実日付から作る。
選択した家の存在確認は現在状態の置換前に行い、失敗時は状態を維持する。
再生準備中の通常通知を抑止し、完了・例外のどちらでも早送り状態を戻す。
過去年代の出来事一覧は、同名・同日の部隊別データを一つの出来事として表示する。

この変更で1534年の配置が実装されたわけではない。1534年のテスト用登録は
起点検出だけを検査する一時的なfixtureで、製品のシナリオには追加しない。
史実DBの候補収集とも別の変更である。

## 検証

- `node tools/checks/history-origin.cjs`：起点、実日付、起点変更時の控え更新、
  起点以前の拒否、未成立の家・不正入力での現在状態維持、正常な移行。
- `node tools/checks/offline.cjs`：基本回帰検査を通過。新しい起点検査を組み込んだ。
- `node tools/checks/organization.cjs`、asset stamps、構文・差分検査を通過。
- 専用Chromeで1400px・390pxを順番に検査。実際のシナリオ選択から時の帯を操作し、
  羽柴家で過去を開けない場合の状態・JSON一致と通知非表示、織田家での正常移行を確認。
  JavaScriptエラーは両幅とも0件。

実画面は127.0.0.1:8000の配信に対して修正した3ファイルを応答差し替えした候補版。
main反映後の通常配信確認とは区別する。
