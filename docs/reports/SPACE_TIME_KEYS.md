# 城の鍵・人物の名前・軌跡を整える

`docs/designs/space-time-records.md` の作業 3 の後半。人物ごと・城ごとの記録が、史実 DB の中で 1 本の線・柱にまとまるようにする。

## 変更

- **城の鍵**：所在の記録（`curated/locations/`）が、ゲームの城の鍵 `castle:<id>`（支配の記録と同じ）を受ける。取り込みは支配の記録と同じく、ゲームの拠点（`node:`・`yosho:`）に結ぶ。城主（`held-castle-lordship`）と持ち主が同じ城に集まる。
- **人物の名前**：所在の記録が、登録の無いゲームの武将も `person:<ゲームの名前>` で受ける（設計では登録のファイルを機械で作る予定だったが、ファイルを増やさない形に変えた）。改名した武将は、ゲームの改名の出来事から 1 人の人物に結ぶ（改名が続く場合は最初の名前まで）。
- **軌跡**：`history_query --path <人物>` が、移動・所在に加えて、城主就任と、生まれた日・死んだ日を出す。その人物が主語の記録だけ（他人の死に関連人物として結ばれただけのものは出さない）。場所の無い点は場所なしで並べ、`--legs`（移動の速さ）は場所のある点だけで計算する。

## 数

改名を結んだので、棚卸しの人物の全体は 431 から 427 になった。

## 検査

- `uv run pytest tests/test_history_queries.py tests/test_history_inventory.py`：PASS（軌跡に生没と城主就任が入る、他人の死は入らない、改名の連鎖が 1 人になる、城の鍵の所在の記録がゲームの拠点に結ばれる）
- `node tools/checks/location-store.cjs`：PASS（登録の無い武将とゲームの城の鍵を受け、知らないものは拒む）
