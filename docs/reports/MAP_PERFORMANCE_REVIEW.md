# 地図表示の軽量化（2026-11-02）

利用者の「開くと重い・パソコンが熱くなる」に対し、地図の再生中の描き直し、起動時の処理、地形タイルの陰影計算を軽くした。史実データ・合戦図（`battle-atlas*.js`）・表示内容は変えていない。

## 変更

| 対象 | 内容 |
|---|---|
| `game/ui.js` 上層描画 | 城・名札・肖像・街道名・合戦地を「静止層」、選択国の縁取りを「下敷き」として別キャンバスに控え、日付・視点・選択が変わった時（再生中は保険で1秒ごと）だけ描き直す。毎フレームは行軍の道筋・駒・移動中の人物・攻城の輪・煙だけを描いて重ねる。重なり順は従来どおり（合戦地の×印だけは移動中の人物の下になる）。 |
| 同 フレームの間引き | 隊と移動中の人物の画面位置が半画素も変わらないフレームは描かない。攻城の輪・煙・交戦の明滅だけの間は約20回/秒。 |
| 同 DOM 更新 | 年表の帯・日付・再生ボタン・速度ボタン・「この先の史実」を値が変わった時だけ書き換える。帯の目盛は日ごとに作り直さず、残りの印が変わった時だけ作る。帯の向き判定（`getComputedStyle`）は画面の大きさが変わった時だけ。 |
| 同 座標変換 | 描画中は画面中心（`vc()`）の結果を控え、1回の描画で数千回の再計算をしない。 |
| 同 停止中 | 停止して何も変わらない状態が1.5秒続いたら、毎フレームの呼び出しを0.2秒ごとの確認に落とす。ポインタ・ホイール・キー・画面サイズの変化で即座に毎フレームへ戻す。非表示タブは従来どおりブラウザが止める。 |
| 同 起動 | 最大縮尺（8倍）でだけ使う「間引かない陸地輪郭」の Path2D を起動時に作らず、初めて要る時に作る。 |
| `game/terrain-tiles.js` | タイルの取得・陰影計算・緯度方向の投影を Web Worker で行い、主スレッドは ImageBitmap を描くだけにした。計算関数は従来と同じものを Worker に渡す。Worker・OffscreenCanvas が無い環境（`file:`、Node の検査）は従来の主スレッド計算。 |
| `tools/checks/load-performance.cjs` | 起動・地形読込・再生中の負荷を測る検査を追加。`GAME_OVERRIDE_ROOT` 指定時は、基準コミットから変えた `game/` のファイルだけを Chrome 側で差し替える（サーバーは起動しない）。 |

## 計測

起動済み8000番（本体の作業ツリー）に専用の一時 Chrome（headless、GPU 無効、1024×768、DPR2、キャッシュ無効）で接続。シナリオ s1585（天正十三年）、近景は大坂付近の1.6倍。改善後は変更ファイルだけを差し替えた。証拠は `data/verification/claude-perf-lighten/{before,after}/load-performance.json`。

| 項目 | 改善前 | 改善後 |
|---|---|---|
| 題名画面の表示まで | 3.2秒（他の回 3.6〜3.8秒） | 1.8秒（他の回 1.6〜2.5秒） |
| load イベント完了 | 34.5秒 | 1.7秒 ※ |
| 起動時の Path2D 作成（CPU） | 約1.4秒 | 約0.17秒 |
| 地形読込中の陰影計算（主スレッド） | 約3秒（読込完了まで、`shade`/`project`/`getImageData`） | 0（Worker） |
| 再生×2 全国：上層の描画回数 | 29.7回/秒 | 7.7回/秒 |
| 再生×2 全国：主スレッド使用率 | 16.2% | 9.2% |
| 再生×2 全国：スクリプト時間 | 5.1% | 1.9% |
| 再生×2 近景：上層の描画回数 | 29.8回/秒 | 16.9回/秒 |
| 再生×2 近景：主スレッド使用率 | 21.4% | 14.1% |
| 再生×16 全国：主スレッド使用率 | 25.3% | 20.1% |
| 再生×16 全国：DOM 変更 | 97件/秒 | 11件/秒 |
| 再生×16 全国：スタイル再計算 | 9.2回/秒 | 5.9回/秒 |
| 地形読込中（九州へ移動、停止中）：主スレッド | 37.2% | 31.2% |
| 停止中：主スレッド | 3.3〜3.7% | 3.4〜3.5% |
| JS ヒープ（再生後） | 79MB | 77MB |
| DOM ノード（再生後） | 5179 | 1730 |

※ Worker の取得はページの load を待たせないため。地形タイルの通信量（題名画面で約950枚、計約83MB）は変わっていない。Worker の通信はこの計測の転送量に数えていない。

- 主スレッド使用率は `Performance.getMetrics` の TaskDuration ÷ 経過時間。headless・GPU 無効のため、キャンバスの合成（`drawImage`）が実機より重く出る。再生×16 の残りの大半は勢力変化による下層の描き直しの `drawImage`。
- 停止中の値は計測用の監視（MutationObserver と自前の rAF）を含み、ループ休止の効果は headless では差として出なかった。
- 静止層・下敷きのキャンバス（画面と同じ 2048×1536、各約12MB、下敷きは選択中だけ）が増える。JS ヒープには現れない。
- 改善前後の画面（大坂付近の近景・中景・選択時）を撮って目視比較し、地形の陰影・名札・駒の見た目に差が無いことを確認した。

## 見送ったもの

- 比較道路（3.2MB）・朝鮮海岸（2.8MB）・湖岸（1.1MB）の遅延読込：起動時の解析は各数ミリ秒で、どれも読込直後に陸地輪郭・湖・街道の表示線（行軍位置の計算にも使う）へ組み込まれる。遅らせると最初の地図と行軍の道筋が変わるため、読込順は変えていない。
- 上層の DPR 上限：文字が粗くなるため、2のまま。

## 未確認・残り

- 既存の実画面検査（`march-clock-browser.cjs`、`zoom-regressions.cjs`、`map-regressions.cjs` など）は 8000番がこの作業ツリーを配信していないため、変更後のコードでは未実行。8000番（本体の未変更コード）では `zoom-regressions.cjs` と `map-regressions.cjs` が失敗しており、これは今回の変更とは無関係。
- 題名画面が地形タイルを約950枚取りに行く点は、起動時の通信量の大半を占める。題名画面だけ1段粗いタイルにすれば約4分の1になるが、見た目が変わるため今回は入れていない。
