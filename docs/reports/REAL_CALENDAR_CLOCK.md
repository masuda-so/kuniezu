# ゲーム時計を実日に接続する

## 問題と維持条件

修正前の `G.date` と内部の `evT` は1年360日・1か月30日を
使っていた。1月31日と2月1日が同じ時刻になり、平年にも2月29日・
30日が生じる。西暦表示で月末を丸めても、出来事の時刻や行軍の
期間は直らない。

史実DBと同じく1582年10月4日までユリウス暦、翌日から
グレゴリオ暦10月15日を使う。これは西暦の表示・比較規約であり、
当時の日本がグレゴリオ暦を採用したという意味ではない。
旧暦は既存の国立天文台由来の月表で引く。

史実の着陣日、保存の資源・所属・領有、移動途中の位置と日内の
進み具合を維持する。保存を読み込んだ際に過去の日次・月次処理を
再実行して資源や年齢を変えない。

## 実装と検証の現在地

`calendar.js` に実日と日番号の相互変換を実装した。不正な月末や
改暦で存在しない日は拒否し、暗黙に月末へ丸めない。
`legacyDate` は旧時計をそのまま読む専用関数で、不正日を保持する。

- `node tools/checks/calendar.cjs`: 1532〜1623年の33,593日を往復確認。
  月末・閏年・改暦境界・非実在日の拒否も確認。
- 同じ33,593日を `kuniezu/history/dates.py` の両変換と照合し全一致。
- 現行の最終読み込み状態にある `TK.HIST` 760件の日付は全て実在日。

新規ゲームは `clockVersion` を付けて実日で進めるように接続した。
版のない旧保存は旧時計として区別する。公開 `G.evT` とengine内の
私有 `evT` の両方を同時に切り替える。タイムラインの年目盛、
盟約の終了翌日、韮山の明渡しまでの在陣も日付から求める。
移動の終了日が未設定のときは、暦日に10を足す代わりに実時刻へ
10日を足す。日付の並び替えでは31日と翌月1日を同じ値にしない。

新規ゲームの暦境界と全760件の実装日付の検査は通過した。
`history-focus.cjs` も通過し、今川の登録出発日・沓掛着陣、清洲同盟、
甲州征伐の領有変更、秀吉の帰還と山崎の順序、および登録済みの
各シナリオから720日間の進行を確認した。検査の合格は、全期間の
史実や布陣の網羅的な照合完了を意味しない。
没日訂正・天正壬午の和睦の対象検査も通過した。ただし、これらは
今回のモデルで生成した訂正前日付の保存であり、実際の旧360日時計
から新時計への移行を検証したものではない。移行の別検査が必要。
旧版の実保存を使った選択移行と実画面の確認は、以下の追加検証で行った。

## 保存移行の設計条件

利用者は2026年11月10日、旧保存が2月30日などを示す場合に
「実在日を選んで移行する」を選択した。元の保存を保全し、
正しい日を一意に復元できるかのような自動補正は行わない。
実在する日を示す旧保存と新規ゲームには選択を求めない。
選択の判定は状態を変更せず、非実在日の直前・直後の実在日を求める。
平年の2月30日は2月28日または3月1日、1582年10月10日は
10月4日または15日になる。これを旧版の実進行で生成した保存でも
確認した。入力元と位置の証拠は
`data/verification/codex-real-calendar-clock/` に保全した。

移行は旧時計で現在位置と日内時刻を採取してから行う。
`schedule`・`visualTravel`・人物の `tr` などの絶対時刻と、兵糧・
日数・待機残日数などの期間は区別する。始終の時刻だけを変換すると
補間率が変わり、軍勢が飛ぶため、移行前の位置から経路を接続する。
史実の予定は実日の到着時刻へ接続する。

`G.evT` の公開関数だけでなく、engine内の私有関数、日付を直接
360日式に直す訂正モジュール、過去再生・早送りのキャッシュ、
履歴・イベント索引、全ての保存読み込み入口を対象とする。
旧署名で判定する既存の修復処理は、時計変換との順序も検証する。

`clock-migration.js` の計画処理は、機械的な期限の残日数と資源・兵数・
処理済みイベント位置を保持する。史実の着陣予定は登録日へ接続し、
表示線の補間率が維持されるよう表示開始時刻を調整する。表示上の
開始時刻を史実の出発日の新資料として扱わない。

旧版の関ヶ原シナリオからも保存を生成した。1560年の保存だけでは
検出できなかった家康の合成軍の位置ずれを再現し、次の所在記録へ
接続する表示経路で解消した。確認した1通常隊・2記録軍の位置差は
1e-7ゲーム座標単位未満。経路の始終と日程は旧表示と既存記録に
基づくもので、史料の新たな所在観測として登録しない。
選択日が既存の着陣期限に達して位置の維持と両立しない場合は、
問題を計画結果に残し、黙って着陣日を遅らせない。

## 読込と実画面の検証

ブラウザ保存、ファイル取込、起動時の状態復元は、共通の読込処理を
使う。補正前原文のバックアップを作り、読み戻して一致を確認してから
再開する。日付の選択前にも原文を保管し、停止時の自動保存による
上書きに備える。容量不足なら現在のプレイを変えず中断する。
補正前の原文は保存・読込メニューから書き出せる。

独立レビューで3点を追加修正し、`clock-load.cjs` に再現検査を加えた。
表示キャッシュのない実軍も道上の点を採取する。木崎原は表示上の
当日内の着陣時刻を維持する。後の実在日を選んだときに未処理だった
出来事は、日付を進めず選択日で反映し、再読込では重複適用しない。

専用Chrome（GPU無効、DPR1）、940px・335pxで18条件を確認した。
候補ファイルの差し替えによる検証であり、通常配信の確認とは別。
18条件19.180秒、JavaScript例外0件。日付選択・取消し、原文保全、
容量不足、軍の位置、再読込、書き出し原文一致を確認した。
木崎原は旧版の実進行の保存、キャッシュ欠落軍は人工的に経路と
期間を設定した回帰検査であり、その布陣を史実として採用しない。
