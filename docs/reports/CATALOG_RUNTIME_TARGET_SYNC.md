# 作業台帳と現行対象の差分同期

## 問題と変更

2026年11月3日のカタログは1526行で、現行モデルにある15拠点IDと、釜山鎮・設楽原・長久手の3合戦図が未登録だった。旧111図という固定値も現在の114図と一致していなかった。旧座標ID2件も残るため、単純に差分13拠点として処理しない。

`node tools/work/build-catalog.cjs --sync-runtime-targets`で、登録済みモデルの拠点と図の不足IDだけを追加する。既存行を変更せず、旧座標IDも保持する。初回棚卸し用の全生成はカタログが存在すれば拒否し、進行中の担当や証拠を上書きしない。新規対象は1534〜1615年の未照合対象として登録し、史実確認済みや戦略地図で使用する対象とは扱わない。

同期後は1544行、カタログの拠点463・図114。現行登録拠点461とは旧記録の分だけ異なる。`conflicts.json`で種類が明示された10図は戦役・個別合戦の参照を保持し、それ以外104図は未分類と数える。114すべてが史実配置を確認済みの局地戦という意味ではない。

## 保持と検査

旧1526行はバイト単位で保持し、7担当記録と3完了記録の内容ハッシュも不変。不足時の`--check`が無変更で失敗すること、再同期は日時を含め無変更になること、重複・ID衝突・曖昧な分類を拒否することを検査した。既存の初回生成と要望方針の同期も隔離ツリーで回帰確認した。

`organization.cjs`・`work-policy.cjs`・`infrastructure.cjs`・要望方針の`--check`が通過。DBの入力全件保持・再取込冪等性・合戦分類の既存3検査も11.73秒で通過した。独立したCodex担当が読み取りで変更を確認し、修正必須の指摘はなかった。[検証要約](../../data/verification/codex-catalog-target-sync/README.md)。

## 範囲と残る受入

今回の同期は拠点と合戦図に限定する。街道・人物・領土移転などの現行対象との差分、各対象の史料照合と実画面の確認は引き続き必要。カタログの追加や構造検査だけで完了率を増やさない。旧記録の受入年代と新しい1534年開始の条件も区別する。

main860e1882起点の専用ブランチで作業。ゲームコード・通常配信DB・サーバーを変更していない。利用者指示によるClaude通信停止を維持し、PR作成と通常配信への反映は保留している。


追加の保持対策として、カタログとmanifestを自分の一時ディレクトリへ先に書き、読み取り時の入力と一致することを再確認してから個別に置き換える。準備失敗・入力の競合時には原本を変更せず、一時ファイルを片付ける検査を追加した。2ファイル同時の取引ではないため、置換途中の中断によるmetadata不一致は`--check`で検出して再同期する。変更のない再実行は書込みを行わない。

必須の`node tools/checks/offline.cjs`も最後まで通過（終了コード0）。生成された監査差分は別途証拠へ保存した。この同期は専用作業ツリーで排他的に実行する前提で、入力比較から置換までを他プロセスに対してロックする仕組みではない。
