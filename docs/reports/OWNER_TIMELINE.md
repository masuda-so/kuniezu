# 城の持ち主を史実 DB から決める（PR 7）

`docs/designs/county-territory.md` の PR 7。史実 DB の支配の記録から書き出した城の持ち主の区間（`history/owners.js`）を、ゲームが読んで年表の持ち主を直す。これで、**DB の記録を変えると、公開版のゲームの城の持ち主と郡の色が変わる**。

## 流れ

```text
data/research/curated/control/*.json（支配の記録、出典付き）
  → node tools/research/export-evidence.cjs（検査、control.jsonl）
  → manage.py import_history（史実 DB）
  → manage.py export_game_data（history/owners.js、城ごとの区間）
  → owner-timeline.js（ゲームが読み、年表を直す）
```

公開の書き出し（`scripts/build_static.py`）は、一時の DB でこの流れを自動で通し、ページの `owners.js` の確認値を付け直す。コミットされている `owners.js` は空の既定（`TK.OWNER_TIMELINE=null;`）で、開発サーバーと検査はこれを読むので、ゲームは今までと変わらない。

## 当て方

設計の「出来事から城を抜き、区間の外を年表に任せる」は、記録がまばらな今、区間が長いほど年表の正しい受け渡しを消してしまう。そこで、記録を**持ち主が替わる点**として当てる形にした（設計書に追記）。

- 行軍拠点の城：区間の始まりの日に、軍勢を出さない受け渡しを足す。同じ家に渡す年表の出来事（入れ子の `take` を含む）が記録より前（3 年以内）にあれば、その出来事からこの城だけを抜く。前の区間と同じ家でも、その間に年表が城を別の家へ渡していれば、後の区間で戻す。記録より後の同じ家への受け渡しは、城が既にその家のものなので何も起きない。
- 行軍拠点でない城：`G.yOwner` を包み、区間の中ならその家を返す。
- 区間は、年表がその城を別の家に渡す日（その家の吸収・全城の明け渡しを含む）で終わる。記録の無い後の歴史は年表のまま。
- 新しいゲームの開始日が区間の中なら、初期の持ち主をその家にする。古い保存の読み込みでは変えない。置き換え前の年表の署名を持つ保存は、読み込む前に年表の位置（`S.hi`・`S.pm`）を引き直して署名を付け替える（`G.fixHist` と同じ手順）。これで、署名の一致を求める古い保存の移行（城の位置など）がそのまま動く。没年の訂正の判定は、置き換え前と今の年表の両方の署名を見る。

`engine.js` と `battle-timing.js` は変えていない。

## 確かめたこと

`node tools/checks/owner-timeline.cjs`（CI に追加、約 2 分半）：

1. 既定（`null`）では年表もその署名も変わらない。
2. 年表より遅い記録（架空：佐和山城を 1560-10-20 に浅井へ）では、年表の 1560-9-20 の受け渡しから城が抜け、10-1 は浅井でなく、10-21 に浅井になる。
3. 東海の試行の 10 記録から書き出した固定の `owners.js`（`tools/checks/fixtures/owners-trial.js`）と既定を、同じ乱数の種で 5 年並べて流す。
   - 最初の記録の日までは、全ての城の持ち主が同じ。
   - 吉田城は記録の日（綱文 永禄7年6月20日＝1564-7-28）の翌日に徳川のもの。既定の年表では 1565-4-10（「三河平定」）まで今川のまま。
   - 区間の中の行軍拠点の城は、家が生きていれば区間の家のもの。
   - 既定と持ち主が違った城は吉田城だけ。
4. 1570・1575・1582・1600 年のシナリオの開始で、区間の中の城の初期の持ち主が区間の家。
5. 入れ子の `take`（「岐阜の池田領への再配分」）より遅い記録で、その `take` から城が抜ける。同じ家の区間の間に年表が城を動かしたときだけ、後の区間の受け渡しが足される。

`node tools/checks/with-owner-timeline.cjs <検査>`（CI に追加）で、古い保存の検査 4 本（`castle-era-position`・`chronology-migration`・`verified-death-dates`・`clock-migration`）を試行の書き出しを読ませて流し、すべて通る（設計の項目 43）。

## 残り

- 記録の家が、年表ではその日（またはそれより前）に滅ぶ場合、記録は効かず、持ち主は年表のまま（`G.ownerInterval` も区間を返さない）。滅んだ家を記録のために生かすと engine 全体に関わるので、記録と年表の食い違いとして扱う。被覆の報告に食い違いとして出すのは今後。

- 家の誕生（`newclan`）が記録より早く城を渡す場合、その出来事の城が記録の城だけなら抜かない（抜くと家が生まれない）。その城は年表の日に渡る。

- 係争（`contested`）の区間の 2 色の斜線（設計の項目 41）は、まだ描かない。
- 記録より前の吸収（`absorb`）が記録の城を動かす例は、まだ無い。出たら設計の `keep` を足す。
