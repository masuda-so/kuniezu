# 検査を減らさずにCIの時間内訳を採る

Django CIの通常のpytestへ`--durations=20`を付ける。
対象・収集規則・試験数・失敗判定・依存関係は変更せず、遅い試験と準備の時間を
既存ジョブのログに出す。追加の全件検査ジョブは作らない。

[pytest公式の時間計測](https://docs.pytest.org/en/stable/how-to/usage.html#profiling-test-execution-duration)
と、配信元venvの`python -m pytest --help`でオプションを確認した。
公式機能の利用であり、これ自体を高速化の達成とは扱わない。

既存の成功CIではpytestが6分34秒〜13分08秒を占めたが、個別試験は未測定だった。
Claudeの同じ端末での史実試験148〜150件は250〜276秒（報告値）で、これも個別内訳は無い。
初回の通常CIの実測から、重複準備の共有、実装の改善、分割可能性のどれを選ぶか判断する。
検査の省略、失敗の無視、必須チェック規則の緩和は行わない。

手元ではオプションの存在と差分を確認し、計測だけを目的とした全件の再実行はしない。
実行時間の結果はこの変更のCI完了後に確認する。
