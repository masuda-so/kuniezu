# 清須会議後の三法師・宗家継承と所在表示

清須会議の継承決定、宗家の管理本拠、三法師の預かり先を分離した。旧保存も含め、預かり期間は岐阜に表示し、引取後の未確認期間を安土への移動で埋めない。基準は main `5217b126782755ed4e451af418d7a6dac8494f86`。独立レビューで判明した初版の3件（旧保存の安土表示、期限後の架空移動、岐阜在城一覧からの欠落）を訂正した候補である。

## 史料と年代

松下浩／滋賀県文化スポーツ部文化財保護課「本能寺の変以後の安土城と織田家」（2024年3月2日）。[現行配布PDF](https://www.pref.shiga.lg.jp/documents/2526/5456533_1.pdf)、[開催記録](https://www.pref.shiga.lg.jp/sd00/2526.html)。25頁、7,496,277 bytes、SHA-256 `2261b7e501f62928b9340bd49928740a1fc453970d42f0d4e571287b8def79a1`。原本はGit外の資料保管庫に保持し、公開ノートは archiveKey と取得URL・SHAで参照する。

- PDF20・節6〜7：旧暦6月27日の家督決定と、信孝による岐阜預かりは講師の説明。会議日を岐阜への到着日にしない。
- PDF20〜21：8月11日秀吉書状、9月3日勝家書状の翻刻。10月にも未入城という説明は21頁にあるが、該当10月書状の翻刻・個別日は掲載されない。
- PDF22末〜23上：博物館蔵の三宿老連署状の翻刻。旧暦12月21日の受取・供奉を記し、安土到着・道筋・出発時刻を直接証明しない。直前の上原氏蔵217号連署状写とは別文書。

旧URLのWeb索引による先行確認と、今回回復した公刊PDFの確認を区別する。16世紀書状の現物・影印を再読したという意味ではない。詳細は `data/research/source-notes/sanboshi-custody.json`。

## ゲームへの接続

7月16日の会議の後に三法師を宗家当主に置き、翌日の信雄分家より先に継承を反映する。宗家本拠は安土（`kannonji`）、本人の預かり先は岐阜（`gifu`）。信雄が尾張織田へ移った後も宗家当主に残る不整合と、本拠が厩橋へ落ちる代替処理を防ぐ。

`TK.DOCUMENTED_RESIDENCES` は人物・所属・居所・出典・命題・半開期間・原暦・境界の意味を持つ。保存には記録IDを付ける。預かり期間の索引は表示7月16日から1583年1月14日までで、毎日の独立した所在観測ではない。期間後は `G.documentedResidence` が `unknown / at:null / arrivalDate:null` を返す。

- `personPoint` は有効な預かり地点を返し、unknownではnullを返す。管理用 `g.loc` や古い補間へ戻らない。
- `syncDocumentedResidence` を読込時と連続移動時に共用する。預かりを移動経路にせず、unknownでは古い `tr` と `_visualPoint` を除く。行政再配分で管理locが変わっても人物の道筋を作らない。
- `displayCastleGens` に預かり人物を表示用として加える。記録が有効な預かり・期限後の所在不明は `castleGens` と `idleGens` の軍事候補からも除く。通常人物の適格条件は維持する。unknownの人物を管理ノードの在城者にしない。
- 城の主肖像・城主選定から預かり人物を除き、詳細・ツールチップに所属と預かり先を明記する。通常の在城者の人数省略で預かり表示を隠さない。攻城相手の選定は軍事APIを使う。
- 後年の明示再配置は過去の記録IDを解除する。既存1592年の岐阜城主イベントを局所適用して、通常表示への復帰と、未確認期間を通る補間がないことを確認した。1592年の詳細日付自体を今回新規認証したものではない。

表示側の追加走査は預かり記録に対応する城と人物だけで行い、全城で全人物の史料判定を繰り返さない。全7か所の `personPoint` 呼出先を確認し、nullを管理座標で埋め直す呼出元はなかった。

## 旧保存

7月16〜17日の旧保存は人物生成前のため、史実保存・対象年代のシナリオ・宗家健在・未生成に限り補完する。7月18日以後の旧人物は管理locを保持したまま表示用記録を付ける。canonical alias、生年・能力値・宗家当主・管理本拠・旧管理ノードを照合し、分岐、既存軍勢、移動中、別の所在記録・ノード・明示待機移動を除外する。後年の基準シナリオを巻き戻さない。

日付・軍勢・領地・年表を再演せず、2回読込でも人物・年表が増えない。記録を持つ期限後保存に古い補間が残っていても、読込直後から抑止する。

## 親側の追加確認

旧実装の3境界日保存を圧縮fixtureとして保持し、元JSONのSHAを検査して読込む。
7月16日と旧18日のように管理ノードと所有家が一致する場合も、預かり・unknownは
軍事要員に含めない。後年の明示配置で記録が解除されれば通常の候補へ戻る。
日付・領地・軍勢・年表・重複読込をCIでも確認し、長期間の日送りに依存させない。
