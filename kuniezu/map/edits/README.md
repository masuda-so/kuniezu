# 地形差分の入力

領域画像の基準版へ時期別の変更を適用する開発用入力。ブラウザには生成済みタイルとマニフェストを配る。

## 現行の正本と年代差分

児島湾・水島の全期間に有効な5補正は、`kuniezu/map/control/provinces.png` 自体へ焼き込む。1560～1583年とタイトル画面はこの正本の形を使う。`applied/` は適用履歴で、生成器は再適用しない。1584年以後の宇喜多堤の366画素を `kojima-bay-ukita-land-from-1584.json` に保持する。遼東基幹域も正本へ入り、1573〜1605年の寛甸軍政域参考は別の年代差分とする。1603〜1605年の撤収過程を含む年精度の表示区切りで、一斉の領有変更を意味しない。1584年1月1日の切替は年精度の仮定で、築堤月日を断定しない。

正本4入力の確認値と適用履歴は [baseline-ledger.json](baseline-ledger.json)。`baselineCommit` は既存スキーマ名だが、画像移行後は基準版IDを格納する。正本の一致は `sourceSha256` で検査する。

通常の再生成は次の順。`build-provinces.cjs` は旧ベクトルからの初回移行専用で、正本が存在すれば上書きを拒否する。`bake-kojima-baseline.cjs` と `tools/geo/kojima-bay-1600.cjs` も旧基準限定の移行記録で、再適用しない。

```sh
node tools/map/build-map-tiles.cjs
node tools/map/build-province-edits.cjs
node tools/map/build-edges.cjs
```

以下の旧基準番号・旧生成結果は移行前の記録。

## 差分のメタデータ

| 項目 | 内容 |
| --- | --- |
| `id` | 変更の固定ID。表示名やファイル名を変えても維持する |
| `layer` | 領域・陸海、標高、河川のいずれか。陸海と領域IDは同じ領域画像の分類 |
| `baseRevision` | 差分を適用する直前の基準版。基準タイルのハッシュで適用前の状態も照合する |
| `validFrom`, `validUntil` | ゲーム内での有効期間。開始を含み終了を含まない。史料の年代幅は根拠の情報へ別に記録 |
| `bounds`, `payload` | 対象範囲と局所の置換値。可逆画像の対象外を示すマスクは水域IDや未割当IDと分ける |
| `sourceIds`, `basis`, `review` | 出典ID、読図・測定・推定の区別、確認済み範囲と残る不確かさ |

同じレイヤー・同じ有効期間で実際に書き換える画素が重なる差分は、入力順で解決せず生成時に停止する。領域画像から、領域色・陸海判定・共有境界・隣接を同じ版として生成する。地形の変化が確認できた時点だけを適用し、位置や日付の分からない中間状態を補間しない。

## 移行時の差分

ロード済みの地形から最初の領域画像を作る場合、その地形に反映済みの補正IDと対象範囲を基準版に記録する。既に適用した差分は、資料として保持しても再適用の対象から外す。

| 既存データ | 初回移行で確認すること |
| --- | --- |
| 曳馬―掛川の管理境界 | 基準版に含まれるか。両領域の外周を維持し、推定管理境界と史実の領有を区別する |
| 今保―十日市の北岸と早島の丘陵 | 陸海・管理領域の両方が反映済みか。慶長図から読んだ岸と現代標高から補った丘陵の根拠を分ける |
| 天竜川・大井川の比較線 | 現代河道の参照データとして保持する。河川画像へ変換しても史実河道の確定には使わない |
| 香取海・児島湾の未採用候補 | 出典照合を続ける。候補の座標を基準版や配布用の年代差分に混ぜない |

100mで失われる島・狭窄部を一覧化し、海・湖・未割当の混同、タイルをまたぐ境界、斜め接触による隣接の増加を検査する。既存セーブとの比較では、城と道路のID、軍勢の経緯度、日内の行軍進捗を確認する。

現行基準版 `71f396b` の実績は [baseline-ledger.json](baseline-ledger.json)。早島・塩津潟は基準画像に含まれるため、旧差分の定義は `applied/` に保管する。生成器は現行基準と差分のハッシュを照合し、適用済みIDの重複を拒否する。以下にある拡張基準版 `9586ebd` の生成結果は移行前の比較記録で、現行版の差し替えには使わない。

## 領域差分の生成

`node --max-old-space-size=6000 tools/map/build-province-edits.cjs` で、全部の期間の版をまとめて作る（下の「Node 版の生成と型紙の差分」）。基準版は正本 `kuniezu/map/control/`（全域1枚の `provinces.png` ほか）で、台帳 `baseline-ledger.json` の `sourceSha256` と照合する。旧 Python 版は廃止した。

領域差分は `payload.file` の GeoJSON、`payload.feature` の配列番号、変更前後の `fromKey`・`toKey` を指定する。基準版と元タイルのハッシュを検証し、100m画素の中心が面の内部にあるところだけ置換する。選択年に重複する書き込み、すでに基準版へ反映したID、変更前の値の不一致は生成エラー。出力は変更タイルと検査用マニフェストで、基準版には書き戻さない。描画側への接続と、標高・河川の差分生成は別工程。

領域の隣接検査は、Pillow・NumPy を入れた Python で `python3 tools/map/audit-raster-adjacency.py kuniezu/static/kuniezu/map/build` を実行する（区画の表は正本 `kuniezu/map/control` から読む）。100m基準版（0d92c0a）では全画素が定義色に一致し、城・中立領域の4近傍と8近傍はいずれも301組で、斜め接触だけの組は0。タイル角をまたいで斜めに接する合成入力では4近傍が0、8近傍が1になることを確認した。海峡の接続特例や道路グラフはこの画素検査の集計に含めない。

天竜川・大井川の現代比較データで、共通の2タイルへ2,043画素と1,716画素をそれぞれ生成した。元データの出典・ODbL・現代比較レイヤー区分をマニフェストへ保持する。既存ゲームの河川表示への切り替えは未実施。

## 標高の生成

（削除済み）旧 `build-height-raster.py` による地理院標高の試験変換。標高の正本は `kuniezu/map/physical/heightmap.png`、陰影は `tools/map/build-height-cache.py`。以下はその時の記録。

早島の6入力タイルから有効標高2,360画素の1タイルを生成した。鶴崎神社の確認点を含む100m画素の標高値は9.75mで、元の細かい格子で現所在地を直接採取した12.27mとは異なる。入力タイルのハッシュと符号化を出力マニフェストに記録した。広域生成、朝鮮側の標高入力の変換、陰影描画への接続は別工程。

## 時点別タイルの受け渡し

`validFrom` と `validUntil` は `[年,月,日]`。生成時に `--date 1600-09-15` または `--year 1600` を指定する。出力には同じ差分集合が有効な半開区間、版ID、差分ID、ハッシュと、100m・400m・800mの変更タイルだけが入る。粗い段は基準版と同じ最近傍の規則を使う。

[早島の生成結果](compiled/15600101-16160101/manifest.json)は、100mの9画素だけが変わった例。400m・800mの画素中心は丘陵に当たらないため、この2段の差し替えはない。縮尺により省かれる小地形と、年代差分が存在しない状態は別。粗い段だけで小島の当たり判定を確定しない。

このマニフェストは差分の受け渡し用。共有版に載せる際は `factor` ごとに既存マニフェストの `tiles` または `levels[].tiles` へ追加し、`file` は対象ディレクトリからのファイル名へ正規化する。基準版のタイル行は残す。

### 早島の適用前後を比較

```sh
python3 tools/map/audit-raster-adjacency.py /path/to/baseline/kuniezu/map
python3 tools/map/audit-raster-adjacency.py /path/to/baseline/kuniezu/map \
  --overlay kuniezu/static/kuniezu/map/build/edits/compiled/15600101-16160101
```

基準版と適用後の `fourNeighbourPairHash` および `eightNeighbourPairHash` はいずれも `72e0703ecb4b1655ccbb86b3fb3b707f62c2de85ecb5d0c944e5052fa797d2e0`。100mで1タイルを置換し、`sea` は9画素減、`castle:bmatsuyama` は9画素増。組数だけでなく隣接するIDの組が一致する。比較には同一基準版のID表を使う。監査は100mの合成結果を対象とし、ブラウザによるタイル選択や描画は別途確認する。

塩津潟の旧マスクは、修正後のベクトル版に合わせて基準版の `lake:139.32,37.98`（旧 `lake:0`）の全5,500画素を既存の `castle:shibata` に置き換える。全画素が修正後の新発田領域に入ることを確認した。湖岸復元や新たな知行認定ではない。ほかの湖のIDは固定。早島との合成後も4近傍・8近傍の隣接組とハッシュは同一だった。

全タイルを読み直した結果、塩津潟の差分画素は100mで5,500、400mで343、800mで85。各段で `lake:0` の残存は0。差分の全画素が `lake:0 → castle:shibata`、または早島の `sea → castle:bmatsuyama` のどちらかであり、後者は100mの9画素のみ。差分タイルのSHA-256はマニフェストと一致した。

正式な拡張基準版 `9586ebd`（20,782 × 24,288画素）で両差分を再生成。100mの変更数は早島9・塩津潟5,500、隣接組は301。旧格子のタイルはこの版と混用しない。

統合基準版 `eeb6275` では、旧差分が変えた全5,937画素の区画キーが新基準と一致した。内訳は早島100mの9画素と、塩津潟100m・400m・800mの5,500・343・85画素。比較は旧基準と旧差分の間で変わった画素に限定し、新旧それぞれの定義表でRGBを区画キーに変換した。旧差分は適用履歴として参照し、実行時は新基準の画素を使う。

同基準版の専用Chromeでは倍率8で早島と塩津潟の確認点をクリックし、100m判定と実際の選択がそれぞれ備中松山城・新発田城で一致した。JavaScript例外0。

統合基準 `3ab7e5f` 向けに、稼働する版付き差分を水島東西の補正へ更新した。早島・塩津潟の旧差分ファイルはGit履歴で参照でき、現行基準には適用済み。水島東西はこの基準の領域画像から100mで644・216画素を海へ置換する。

## Node 版の生成と型紙の差分

`node --max-old-space-size=6000 tools/map/build-province-edits.cjs` で全期間の版をまとめて作る。全部の版を作り終えてから一時置き場に書き、置き場ごと入れ替える。負例の検査は `node tools/checks/province-edits.cjs`。差分の期間の境目ごとに半開区間の版を一つずつ `compiled/<開始>-<終了>/` に書き、使わなくなった版の置き場は消す。規則は Python 版と同じで、水島の3差分だけで作り直した結果は既存の版と画素が一致した。

`payload.mask` の差分は、100m格子の窓 `window`（列・行・幅・高さ）に合わせた PNG を型紙にする。画素の値 n（G が上位、B が下位）が1以上なら `keys[n-1]` を書き、`from` が `land` なら元が陸、`sea` なら元が海であることを確かめる。`maskSha256` で型紙の取り違えを止める。

児島湾の3差分（`kojima-bay-*.json`）は `tools/geo/kojima-bay-1600.cjs` が作る。根拠は `docs/reports/BIZEN_NORTH_SHORE_REVIEW.md` の「児島湾全体」。

## 遼東の軍政域参考

`data/research/liaodong-reference/liaodong-1560.geojson` の基幹域を、未割当と旧 `neutral:明` だけへ適用した。海・湖・城領は保持し、基幹域外の旧明を未割当へ戻す。女真等の確定領土へ自動割当しない。正本の変更前後は `data/verification/liaodong-source-baseline/`。

寛甸の差分 `ming-kuandian-1573-1605-reference.json` は [1573,1,1]〜[1606,1,1) の年精度の表示。`payload.from: "key:unassigned"` で未割当画素だけを対象にする。1573築堡開始、1603〜1605撤収を併記し、軍・外交・行軍の所属へ転用しない。宇喜多期との組合せで配信用の版は1573–1584／1584–1606／1606–1616の3版になる。正本は1560年の基幹域。
